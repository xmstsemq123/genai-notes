# 跟 AI 討論 AGENTS.md 的紀錄

老師在第 09 週的講義說，AGENTS.md 這種規格書會由我們和 AI 討論出來。這份是我討論的完整紀錄。對話的 AI 是 Claude，我在 Claude Code 裡另外開一個對話，請它當一般的聊天 AI 回答，不讓它碰檔案。

- 第一輪：AGENTS.md 要寫什麼、資料夾和檔名、每頁的區塊、怎麼放進「成品、限制、完成標準」
- 第二輪：JS 和字型的例外、名詞索引、哪些規則可以交給腳本、寫作規則
- 第三輪：開一個全新的對話，只叫它讀 AGENTS.md，請它做第 08 週的筆記，看規則哪裡沒寫清楚

AI 的回答照原文保留，沒有修改。最後一段是我採用和沒採用的地方。

## 第一輪

### 我的 Prompt

> 我是電機所碩一的學生，這學期在修生成式AI。這週作業是要自己設計一個小專案，然後寫一份 AGENTS.md 或 CLAUDE.md，讓 AI 讀完就知道這個專案要怎麼繼續做下去，最後要放上 GitHub Pages 變成可以看的網頁。老師說重點不是把一個網頁做出來，而是建立一套規則，之後可以照同一套方式很快做出新的頁面。
>
> 我想做的是「生成式AI 課後筆記站」。每週上完課我把那週的講義整理成一頁筆記，目前手上有第 06 到 09 週的講義（06 打造自己的對話機器人、07 RAG 跟 LLM Wiki、08 AI Agent 的設計模式、09 Agentic Work 跟 AGENTS.md）。之後每上一週課，我只要把講義丟進資料夾，跟 AI 說「幫我做第 10 週的筆記」，它就能照規則做出一頁風格一樣的筆記。
>
> 我的想法是用純 HTML + CSS，不要用框架，因為 GitHub Pages 直接就能跑，AI 改起來也比較不會出錯。
>
> 想請你幫我想幾件事：
> 1. AGENTS.md 裡面應該要寫哪些東西？我不想寫成很空泛的「請保持風格一致」那種。
> 2. 資料夾跟檔名要怎麼安排比較好？
> 3. 每一頁筆記應該固定有哪些區塊？我希望不是只有把講義抄一遍，要有我自己的理解。
> 4. 老師上課有說好的交辦要講清楚「要什麼成品、有什麼限制、怎麼算做完」，這個要怎麼放進 AGENTS.md？

### AI 的回答

這題目挑得不錯，筆記站本來就是同一種頁面一直重複做，很適合拿來練「建規則」。下面照你的四個問題回答，最後附一份 AGENTS.md 骨架，你可以直接拿去改。

#### 先講一個大方向：規則要寫成能檢查的

「請保持風格一致」很空，是因為 AI 沒辦法自己判斷有沒有做到。比較好的做法是讓每條規則都能被驗證：

- ❌ 請保持風格一致
- ✅ 新頁面一律從 `templates/note-template.html` 複製；只能用 `assets/style.css` 裡已經有的 class；不准寫 inline `style=""`，也不准新增 `<style>` 區塊

再來，**範本檔比文字描述有用**。你寫十行去形容版面長怎樣，效果通常不如直接給一個 template，再指定一頁做好的筆記當參考範例（例如「第 06 週是標準範例」）。AGENTS.md 負責講規則跟流程，長相就交給範本檔。

#### 1. AGENTS.md 裡要寫什麼

我建議分成這幾段：

1. **專案目的（2～3 句）**：這是什麼網站、給誰看、為什麼是純 HTML/CSS。AI 知道原因，遇到規則沒寫到的狀況比較會做出合理的判斷。
2. **資料夾結構**：每個資料夾放什麼，哪些可以改、哪些不准動。
3. **標準流程**：使用者說「幫我做第 N 週的筆記」時，第 1 步做什麼、第 2 步做什麼，一步一步寫出來。
4. **頁面結構規則**：必要區塊有哪些、順序、每個區塊大概多長、用哪個 class。
5. **內容規則**：用語（繁中、台灣用語）、專有名詞第一次出現要附英文、哪些內容一定要出自講義、哪些內容一定要出自你本人。
6. **禁止事項**：不准引入框架或 CDN、不准改 `style.css`（除非你明確要求）、不准編造講義裡沒有的內容、不准自己生出「我的心得」。
7. **完成標準（Definition of Done）**：一份勾選清單，後面第 4 點會細講。
8. **不確定時怎麼辦**：例如「講義內容不清楚的地方，留 `<!-- TODO: ... -->` 並在回報中列出，不要猜」。很多人會漏掉這段，但它能大幅減少 AI 亂編。

#### 2. 資料夾跟檔名

```
/
├── AGENTS.md
├── README.md
├── index.html              ← 首頁，列出所有週次
├── .nojekyll               ← 空檔案，叫 GitHub Pages 不要用 Jekyll 處理
├── assets/
│   ├── style.css           ← 唯一的樣式檔
│   └── img/
│       └── week-06/        ← 每週的圖片各放一個資料夾
├── templates/
│   └── note-template.html  ← 新筆記的起點
├── notes/
│   ├── week-06.html
│   ├── week-07.html
│   └── ...
└── sources/
    └── week-06/
        ├── slides.pdf      ← 講義
        └── my-notes.md     ← 你自己的想法（很重要，下面會說）
```

幾個細節：

- **檔名用英文小寫、數字補零、用連字號**，像 `week-06.html`。不要用中文或空格，放上 GitHub Pages 之後網址會被編碼成一串 `%E7%94%9F...`，很難看，也容易出錯。補零之後排序才會正確（`week-10` 不會排到 `week-09` 前面）。
- **檔名只放週次，不放主題**。`week-07.html` 比 `week-07-rag-llm-wiki.html` 好，因為 AI 只要知道週次就能推出檔名，不會出現每次命名都不一樣的狀況。主題寫在頁面標題就好。
- **一律用相對路徑**（`../assets/style.css`）。GitHub Pages 的網址通常是 `帳號.github.io/repo名稱/`，用 `/assets/...` 這種絕對路徑會指錯位置。這條也要寫進 AGENTS.md。
- **講義 PDF 要不要上傳到公開 repo，建議先問老師**。講義的著作權是老師的，你可以把 `sources/*.pdf` 加進 `.gitignore`，只在本機給 AI 讀。

#### 3. 每頁筆記的固定區塊

為了不只是「把講義抄一遍」，我建議區塊這樣排：

| 區塊 | 內容 | 來源 |
|---|---|---|
| **頁首資訊** | 週次、日期、主題、2～4 個標籤 | 講義 |
| **一句話總結** | 這週在講什麼，限 50 字內 | AI 整理 |
| **這週要解決什麼問題** | 為什麼需要這個東西？沒有它會怎樣？ | AI 整理 |
| **核心概念（3～5 個）** | 每個概念包含：定義 → 白話解釋 → 一個具體例子 | 講義 + AI |
| **概念之間的關係** | 一張比較表或流程圖（例如 RAG 的流程、各種 Agent 模式的比較） | AI 整理 |
| **跟前幾週的連結** | 例如 07 的 RAG 是在補 06 聊天機器人的哪個缺點；09 的 AGENTS.md 跟 08 的 Agent 模式有什麼關係 | AI 整理 |
| **我的理解** | 你自己的觀點、類比、跟電機背景的連結 | **只能來自你** |
| **我還不懂的** | 疑問清單 | **只能來自你** |
| **延伸 / 出處** | 講義頁碼、延伸閱讀 | 講義 |

裡面最關鍵的是**「我的理解」跟「我還不懂的」**。AI 不可能知道你怎麼想，如果沒有規則擋著，它就會生出一段看起來很像心得、其實很空的內容。所以我建議：

- 每週丟講義的時候，順便丟一個 `my-notes.md`，隨手寫幾條就好（「RAG 感覺很像快取」、「不懂 chunk size 要怎麼選」這種程度就夠了）。
- AGENTS.md 寫死：**「我的理解」和「我還不懂的」只能根據 `my-notes.md` 改寫潤飾；檔案不存在就留 TODO 佔位，不准自己生。**
- 視覺上也做出區隔，例如這兩塊用 `class="my-take"`，換個底色。看的人（包括老師）一眼就分得出哪些是講義整理、哪些是你自己的想法。

「跟前幾週的連結」也很值得放。它會逼 AI 去讀之前的筆記，你的筆記站就不會只是一堆各自獨立的頁面。剛好你這四週內容本身就是一條線（對話機器人 → 加上知識 → 變成 Agent → 怎麼交辦給 Agent）。

#### 4. 把「成品、限制、完成標準」放進 AGENTS.md

最直接的做法，是把「幫我做第 N 週筆記」這句話**預先展開成一份完整的交辦**，寫在 AGENTS.md 裡。這樣你每次只要講一句話，AI 拿到的卻是講清楚的任務：

**成品（要交出什麼）**
- 新增 `notes/week-NN.html`
- 在 `index.html` 加一張這週的卡片
- 把第 N-1 週頁面的「下一週」連結接上
- 圖片（如果有）放在 `assets/img/week-NN/`

**限制（不能做什麼）**
- 內容只能根據 `sources/week-NN/`，加上已經存在的筆記（寫「跟前幾週的連結」時用）
- 不准改 `style.css`、不准加 JS、不准用外部 CDN
- 不准寫 inline style
- 「我的理解」只能來自 `my-notes.md`

**完成標準（怎麼算做完）**：寫成可以逐條勾選的清單，例如：
- [ ] 所有必要區塊都在，順序正確，每個區塊都有指定的 `id`
- [ ] 核心概念 3～5 個，每個都有例子
- [ ] 所有連結都是相對路徑，而且點得到
- [ ] 首頁卡片已新增，上一週的「下一週」連結已更新
- [ ] 沒有編造的心得，缺資料的地方都留了 TODO
- [ ] 最後回報：改了哪些檔案、還有哪些 TODO 要使用者補

最後一條「回報格式」很好用。AI 做完要交代自己動了什麼，你檢查起來快很多。

#### 最後一個建議

規則寫完之後一定要**實際測過**：06 你自己做（或跟 AI 一起做到滿意），當作標準範例；接著**開一個全新的對話**，只叫 AI 讀 AGENTS.md，請它做 07。AI 哪裡做錯，就代表規則哪裡沒寫清楚，回頭補上，再用 08、09 繼續測。

這個「做 → 抓錯 → 補規則」的過程，很適合寫進作業報告。老師說重點是「建立一套規則」，這段紀錄正好能證明你的規則真的有效，而且是一步步改出來的。

有需要的話，我可以幫你把 template 的 HTML 結構或 style.css 的設計變數先寫出來。

> 4. 我自己寫東西不喜歡用破折號和分號，看起來很像 AI 寫的。我想在 AGENTS.md 加寫作規則，你覺得除了這兩個還要規定什麼，才不會讓筆記讀起來像 AI 生的？

### AI 的回答

你改的這幾個地方都合理，下面一個一個回。

#### 1. JS 和外部資源

你這樣寫可以。我會再補三件事，讓 AI 比較不會誤解。

**第一，寫清楚 site.js 負責什麼。** 如果只寫「全站只有一支 site.js」，之後 AI 想加功能（自動目錄、複製按鈕之類），很可能直接往這支檔案裡塞。建議寫成這樣：

```
- 全站只有 assets/js/site.js，目前只負責深色模式切換和記住使用者的選擇
- 每頁只能用 template 裡那一行 <script> 引入它，不得新增其他 <script>，行內 script 也不行
- 修改 site.js 要先經過使用者明確同意
```

**第二，頁面不能靠 JS 才看得到。** 深色模式先用 CSS 的 `prefers-color-scheme` 做好，讓它跟著系統設定。JS 只負責手動切換，再把選擇存到 localStorage。這樣就算 JS 沒載到，頁面也是正常的。另外加一條「顏色只能用 style.css 裡的 CSS 變數，頁面裡不准寫色碼」。不然 AI 只要在某一頁寫了 `color: #333`，那一頁在深色模式下就壞了。

切換時畫面閃一下白，可以這樣處理：把 site.js 放在 `<head>`、不加 defer，開頭先設好 `data-theme`。這段寫死在 template 裡，AI 就不用每次自己決定。

**第三，外部資源用網域白名單來寫。** 「只允許 Google Fonts」人看得懂，但腳本不好檢查。改成「外部網址只允許 fonts.googleapis.com 和 fonts.gstatic.com」，第 3 題的腳本就能直接比對。字型的 `<link>` 也固定在 template，寫明只載 Noto Serif TC 的 600 和 700 兩個字重，並加上 `display=swap`。內文建議用系統字（微軟正黑體、蘋方），只有標題用襯線字，這樣載入量會小很多。Google Fonts 的中文字型會切成很多小片、用到才下載，檔案大小不用太擔心。

#### 2. 名詞索引

一直加還要保持一致，有兩個原則：一個名詞只能有一個條目，定義寫進去之後不要隨便改。具體可以這樣規定：

- **唯一 ID**：每個名詞用英文小寫加連字號當 id，例如 `term-rag`、`term-harness`、`term-reflection`。id 不能重複，這條交給腳本檢查。
- **別名欄位**：同一個概念常常有好幾種叫法，例如 RAG 和檢索增強生成。每個條目都要列別名。新增之前，先用名稱和別名搜一遍，已經有了就不再新增。
- **譯名表**：在 AGENTS.md 放一張小表，固定哪些詞不翻（Agent、Harness），哪些詞一律用中文。每週翻譯不一樣，是定義不一致最常見的原因。
- **定義凍結**：第一次寫進去的定義不改。之後有新的理解，就在條目下面加一行「第 N 週補充」。如果真的要改定義，AI 要先在回報裡提出來，你同意之後才能改。
- **收錄門檻**：只收該週「核心概念」區塊裡的名詞，每週最多 5 到 8 個。沒有門檻的話，AI 會把每個英文單字都收進來。
- **雙向連結**：筆記頁裡某個名詞第一次出現時，連到 `glossary.html#term-xxx`。索引頁的「首次出現」也要連回那一週。
- **排序**：依英文字母排序，查起來最方便。

每個條目的格式也固定下來，例如：

```html
<dt id="term-rag">檢索增強生成 <span class="en">RAG</span></dt>
<dd>
  <p class="def">先從外部資料找出相關段落，再交給模型一起產生回答。</p>
  <p class="meta">別名：Retrieval-Augmented Generation｜首次出現：<a href="notes/week-07.html#concepts">第 07 週</a></p>
</dd>
```

定義限一句、40 字以內。現在用純 HTML 維護就夠了。等名詞超過七、八十個，再考慮改成 `glossary.json`，由腳本產生 HTML。

#### 3. check.mjs 能檢查什麼

**適合交給腳本的（結構和格式）：**

- 檔名符合 `week-NN.html`
- 必要區塊的 id 都在，順序也對
- 沒有 `style=""`，也沒有 `<style>`
- `<script>` 只有 site.js 一支，而且只出現一次
- 所有外部網址都在白名單裡
- 沒有用 `/` 開頭的絕對路徑
- 所有站內連結和錨點都找得到目標，包括連到 glossary 的 `#term-xxx`
- 圖片檔案存在，而且有 alt
- index.html 每一週都有卡片，上一週和下一週的導覽連結有接起來
- glossary 的 id 沒有重複、排序正確、「首次出現」的週次存在
- 核心概念的數量在 3 到 5 個之間，一句話總結在 50 字以內
- 如果 `sources/week-NN/my-notes.md` 不存在，「我的理解」區塊只能是 TODO
- 第 4 題的禁用字元和禁用詞（記得排除 `<code>` 和 `<pre>` 裡的內容）

**只能人看的（內容和品質）：**

- 內容有沒有忠於講義，有沒有講錯
- 「我的理解」有沒有忠實反映 my-notes.md，有沒有被 AI 加油添醋
- 例子好不好、「跟前幾週的連結」講得通不通
- 名詞定義的意思前後有沒有矛盾（腳本只能確認 id 沒重複）
- 讀起來順不順、深色模式看起來舒不舒服

腳本本身有幾點建議：

- 分成 error 和 warning 兩級，有 error 就讓腳本用非 0 的 exit code 結束。TODO 數量算 warning，列出來就好。
- 每則訊息都寫出檔案、規則名稱和問題位置，AI 才知道要改哪裡。
- 支援 `node scripts/check.mjs --week 10`，只檢查單一週，另外留一個全站檢查的模式。
- 盡量不要裝套件。你的 template 結構很固定，用 Node 內建功能加上簡單的比對就夠用了。

AGENTS.md 裡還一定要加一條：**「不得為了讓檢查通過而修改 check.mjs。檢查沒過就改頁面。如果認為檢查本身有錯，在回報裡說明，由使用者決定。」** 少了這條，AI 遇到檢查一直不過的時候，真的有可能去改腳本。回報的時候也要把腳本最後的輸出一起貼出來。

#### 4. 寫作規則

除了破折號和分號，下面這些都是很常見的 AI 痕跡，可以一起寫進去：

**句型**
- 不用「不是 A，而是 B」這種先否定再翻轉的對比句
- 不硬湊三個一組的排比
- 段落結尾不加一句金句總結
- 少用「不僅……更……」「無論是……還是……」

**開頭和轉折**
- 不用「在當今快速發展的……」「讓我們一起來看看」開頭
- 不用「值得注意的是」「總而言之」「綜上所述」「一言以蔽之」

**禁用詞**
- 賦能、至關重要、無縫、強大的、革命性、深入探討、扮演關鍵角色、旨在、全面提升

**格式**
- 粗體一段最多一處，不要每個條列都寫成「粗體標題：內容」
- 需要解釋因果的地方用段落，不要拆成條列
- 不用 emoji

**語氣和內容**
- 每個說法盡量搭一個具體例子，或標出講義頁碼
- 不誇大，不寫「完美解決」「徹底改變」這種話
- 講義整理的區塊用中性陳述，「我」只出現在「我的理解」裡
- 設定好讀者是誰，例如「寫給一個月後忘記上課內容的自己」。AI 有明確的讀者，語氣會自然很多

**標點**
- 中文用全形標點和「」引號
- 中英文之間要不要空半形空格，選一種就全站統一

比起列一長串規定，**附一組好壞對照**通常更有效。你可以在 AGENTS.md 放兩小段，一段你覺得很 AI 的，一段你自己寫的，標明「要寫成第二種」。AI 模仿範例的能力比遵守抽象規則強很多。

禁用字元和禁用詞清單，可以直接放進 check.mjs 當 warning。這樣第 3 題和第 4 題就接起來了：寫作規則不只寫在文件裡，也能自動檢查。

## 我採用和沒採用的地方

### 採用

- 規則要寫成可以檢查的，所以多寫了 `scripts/check.mjs`，跑過才算做完。
- 範本檔加一頁標準範例，比用文字形容版面有用。第 06 週是標準範例。
- 檔名只放週次（`week-NN.html`），一律用相對路徑，加 `.nojekyll`。
- 講義 PDF 和抽出來的文字不上傳，只在本機給 AI 讀。
- 「我的理解」「這週的作業」「還沒搞懂的」只能改寫 `my-notes.md`，沒有就留 TODO。
- 「跟前幾週的關係」這個區塊。
- 名詞索引的唯一 id、先搜尋再新增、定義凍結加「第 NN 週補充」、收錄門檻、譯名表。
- 外部網址用網域白名單。site.js 放在 `<head>` 不加 defer，避免切換時閃白。
- 「不准為了讓檢查通過去改 check.mjs」這條。
- 寫作規則的讀者設定和好壞對照。
- 固定的回報格式，還有「不確定時怎麼辦」。

### 沒採用或改掉的

- 它第一輪說完全不用 JS 和外部 CDN。我要深色模式和中文襯線標題，所以留一支 site.js 和 Google Fonts。
- site.js 除了深色模式，我還讓它標示目錄目前讀到哪一段。這個寫在 AGENTS.md 第 7 節。
- 字重它建議 600 和 700，我用 700 和 900，因為首頁大標題要比較粗。
- 收錄門檻它說每週 5 到 8 個，我定成最多 6 個，名詞太多索引就不好查。
- 禁用詞它建議當 warning。我把破折號、分號、emoji 和禁用詞都設成 error，只有「不是…而是」句型當 warning，因為這種句型有時候是正常用法，要人判斷。
- 名詞條目的格式我沒照它的 `dt id`，改成整個條目包在 `div.glossary-item` 裡，這樣從筆記頁點過來的時候，整個條目可以一起標示出來。
- 它建議首頁每週用「卡片」。我改成一列一列的目錄，比較像書的目次，週數變多也不會太擠。
